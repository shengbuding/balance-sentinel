# 上位机配置与数据同步接口预留

状态：仅内部契约，未实现网络传输、监听服务或前端入口。

## 当前边界

`DesktopSyncPort` 是未来上位机的传输无关接口，只接收 `InputStream`、`OutputStream` 和受限元数据。Android `Uri`、HTTP、WebSocket、局域网发现、配对界面与服务器实现不属于该接口。

处理顺序固定为：

1. `stage`：按类型限制字节数，流式写入临时存储，同时计算 SHA-256。
2. `preview`：配置必须走 `ConfigImportParser -> BackupImportPlanner`；历史必须走有界 `HistoryJsonReader`。
3. 用户明确确认后调用 `apply`，再次核对摘要、基线 revision 和替换确认。
4. 成功后持久化 `transferId + nonce + digest` 回执，重复请求返回原结果，不重复写入。

配置导入必须继续调用 `RoomConfigImportCoordinator`，历史导入必须继续使用现有暂存、复读校验和 Room transaction 路径。不得调用旧的整文件 `readBytes()` 导入路径。

## 安全要求

- 传输必须使用独立的短期配对会话、TLS 和设备身份；Provider API Key、账户 ID 哈希、同步 URL 都不能充当认证凭据。
- 元数据必须校验 schema、随机 `transferId`、随机 nonce、签发/过期时间、内容长度和 SHA-256。有效期最长 5 分钟。
- 配置上限 4 MiB，历史上限 256 MiB；实际传输层还必须限制并发、速率、分块数量、编码后大小、连接/读写超时和失败重试。
- 默认配置同步不得包含 API Key、额外凭据、自定义脚本或已授权来源。未来若支持凭据，必须是独立显式能力，并复用加密凭据恢复、写后校验和回滚流程。
- 导入内容不得指定同步端点、代理、回调 URL，也不得自动启用或执行脚本。自定义脚本仍需静态检查和用户逐项授权 HTTPS origin。
- 日志和回执只记录不透明 ID、摘要、类型、字节数和结果，不记录凭据、Header、Cookie、脚本正文或完整路径。
- 配置发布必须先于历史导入；外层排他锁需要覆盖两段，避免账户集合变化导致历史被错误过滤。

## 暂不承诺

当前历史记录没有跨设备稳定事件 ID，因此第一版只能支持显式单向导入/导出和追加/合并。双向增量同步、删除传播、自动冲突解决、跨设备去重、后台自动上传、LAN 发现和远端控制均未实现，也不能基于当前本地自增 ID 宣称可用。

在真正实现传输前，README 与隐私政策中的“数据仅本地存储、不会上传”仍然成立。
